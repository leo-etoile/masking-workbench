# 의료 데이터 마스킹 프로젝트 보고서

## 1. 프로젝트 개요

이 프로젝트는 IDSS에 민감정보가 포함된 비정형 프리 텍스트가 들어오는 경우를 대비해,
텍스트 안의 개인건강정보(PHI)를 찾아 마스킹하기 위한 워크벤치를 만드는 것을 목적으로 한다.

진료 기록과 같은 자유서술형 텍스트는 정해진 형식이 없기 때문에 하나의 방식만으로 모든
민감정보를 찾기 어렵다. 이를 보완하기 위해 주민등록번호나 전화번호처럼 형태가 비교적
일정한 정보는 **규칙 기반 모듈**로 찾고, 이름이나 주소처럼 문맥을 함께 봐야 하는 정보는
**AI 모델 기반 모듈**로 찾는 하이브리드 방식을 적용하고자 한다.

## 2. 추진 목적

- 비정형 의료 텍스트에서 PHI를 탐지하고 마스킹할 수 있는 기반을 마련한다.
- 규칙 기반 모듈과 AI 모델 기반 모듈의 결과를 한 화면에서 비교한다.
- 데이터 특성에 맞는 마스킹 방식을 확인할 수 있도록 여러 모듈을 선택해 실행한다.
- 새로운 탐지 모듈을 쉽게 추가할 수 있는 확장 가능한 구조를 만든다.
- 탐지 결과를 사람이 확인하고 수정하여 라벨 데이터셋으로 저장한다.
- 축적한 라벨 데이터셋을 추후 의료 데이터용 마스킹 모델 학습에 활용한다.

## 3. 전체 처리 흐름

1. 사용자가 진료 기록 등의 텍스트를 입력한다.
2. 적용할 규칙 또는 AI 탐지 모듈을 선택한다.
3. 각 모듈이 주민등록번호, 전화번호, 이름, 주소 등의 민감정보 후보를 찾는다.
4. 탐지 위치와 모듈별 결과를 화면에서 비교한다.
5. 사용자가 결과를 확인하고 필요한 라벨을 추가·수정·삭제한다.
6. 확정한 라벨을 데이터셋으로 저장한다.
7. 저장한 데이터는 모듈 성능 평가와 추후 모델 학습에 활용한다.

## 4. 주요 설계

### 하이브리드 마스킹

규칙 기반 방식과 AI 모델 기반 방식을 함께 사용할 수 있도록 구성했다. 현재는 선택한
모듈을 각각 실행해 결과를 비교하는 단계이며, 이후 데이터 유형별 성능을 확인해 가장
효과적인 조합과 결과 병합 기준을 정할 예정이다.

### 모듈 확장 구조

탐지 기능은 모듈 단위로 분리되어 있다. 공통 형식에 맞춰 새 모듈을 추가하면 워크벤치가
이를 자동으로 찾아 목록에 표시한다. 따라서 기존 코드를 크게 변경하지 않고도 새로운
규칙, NER 모델 또는 LLM 기반 탐지 방식을 추가하고 비교할 수 있다.

### 라벨링 및 평가

탐지 결과를 그대로 사용하는 것이 아니라, 사용자가 결과를 확인한 뒤 라벨을 추가하거나
수정할 수 있다. 확정한 라벨은 문서별 JSON 파일로 저장되며, 각 모듈의 탐지 결과와 비교해
정밀도(Precision), 재현율(Recall), F1 점수를 확인할 수 있다.

## 5. 현재까지 진행 상황

현재는 워크벤치의 기본 구조와 주요 동작을 확인할 수 있는 초기 단계이다.

| 구분 | 진행 내용 | 상태 |
| --- | --- | --- |
| 화면 구성 | 텍스트 입력, 샘플 선택, 모듈 선택, 탐지 결과 확인 화면 구성 | 기본 구현 |
| 탐지 결과 확인 | 민감정보 후보 위치 강조 및 모듈별 결과 표시 | 기본 구현 |
| 라벨링 | 라벨 추가·수정·삭제, 문서별 저장 및 불러오기 | 기본 구현 |
| 모듈 관리 | 공통 인터페이스와 자동 탐색 방식 적용 | 기본 구현 |
| 규칙 기반 탐지 | 주민등록번호, 전화번호, 날짜, 이메일 탐지 규칙 추가 | 초기 구현 |
| AI 기반 탐지 | KoELECTRA NER 및 LLM 프롬프트 모듈의 비교용 구조 추가 | 초기 구현 |
| 성능 평가 | 모듈별 Precision, Recall, F1 계산 | 기본 구현 |
| 마스킹 처리 | 탐지 구간을 `[RRN]`, `[NAME]`과 같은 유형값으로 치환하는 기능 | 기본 구현 |

현재 규칙 모듈은 일부 PHI 유형만 처리한다. 이름, 주소, 병원명 등 의료 텍스트에서 자주
등장하는 항목을 위한 규칙과 모델을 추가하고, 실제 데이터 특성에 맞게 탐지 기준을
보완해야 한다.

## 6. 현재 산출물

- FastAPI 기반 탐지·라벨 저장·평가 API
- React/Vite 기반 마스킹 워크벤치 UI
- 규칙 기반 탐지 모듈 4종
  - 주민등록번호
  - 전화번호
  - 날짜
  - 이메일
- KoELECTRA 기반 개체명 인식 모듈
- Claude 프롬프트 기반 PHI 추출 모듈
- 새 탐지 모듈을 자동으로 등록하는 모듈 구조
- 문서별 라벨 저장 및 불러오기 기능
- 모듈별 성능 평가 기능
- 백엔드 및 프론트엔드 테스트 코드

## 7. 향후 계획

1. 이름, 주소, 병원명 등 추가 PHI 탐지 모듈을 개발한다.
2. 규칙별 예외 사례를 보완하고 테스트 데이터를 확대한다.
3. 규칙 기반, NER, LLM 모듈의 성능을 같은 데이터셋에서 비교한다.
4. 여러 모듈의 결과가 겹칠 때 적용할 우선순위와 병합 기준을 정한다.
5. 라벨 검수와 데이터셋 내보내기 기능을 보완한다.
6. 축적된 라벨 데이터셋을 이용해 의료 데이터에 맞는 모델을 학습한다.
7. 충분한 성능 검증 후 IDSS 연계 방안을 구체화한다.

## 8. 기술 구성

- **Backend:** Python, FastAPI
- **Frontend:** React, TypeScript, Vite
- **Rule-based:** Python 정규표현식
- **Model-based:** KoELECTRA NER, Claude API
- **Label storage:** JSON

## 설치

### 백엔드

```powershell
# Windows
cd backend
setup.bat
```

```bash
# macOS / Linux
cd backend
./setup.sh
```

Python 3.13과 최초 의존성 설치를 위한 인터넷 연결이 필요하다.

`klue_ner` 모듈은 최초 실행 시 Hugging Face Hub에서
`Leo97/KoELECTRA-small-v3-modu-ner` 모델을 내려받으며, 이후에는 로컬 캐시를 사용한다.

`llm_prompt` 모듈을 사용하려면 `ANTHROPIC_API_KEY` 환경변수를 설정해야 한다.

```bash
# macOS / Linux (현재 터미널 세션에만 적용)
export ANTHROPIC_API_KEY="your-key-here"

# macOS / Linux (새 터미널에서도 유지, zsh 기준)
echo 'export ANTHROPIC_API_KEY="your-key-here"' >> ~/.zshrc && source ~/.zshrc
```

```powershell
# Windows (현재 세션에만 적용)
$env:ANTHROPIC_API_KEY = "your-key-here"

# Windows (새 터미널에서도 유지)
setx ANTHROPIC_API_KEY "your-key-here"
```

API 실행:

```powershell
# Windows
.venv\Scripts\python.exe -m uvicorn api.main:app --reload
```

```bash
# macOS / Linux
.venv/bin/python -m uvicorn api.main:app --reload
```

### 프론트엔드

새 터미널에서 다음 명령어를 실행한다.

```bash
cd frontend
npm ci
npm run dev
```

프론트엔드는 기본적으로 `http://localhost:5173`에서 실행된다.
